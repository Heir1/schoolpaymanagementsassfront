**Context**
We have completed the landing page.
Now we are implementing **User Management & Authentication** for a school payment platform designed **exclusively for primary and secondary schools**.

The backend API is already available.
The frontend must integrate authentication, roles, permissions, and protected routes.

---

## Authentication Endpoints

### 1️⃣ Login

**Endpoint**

```
POST /api/v1/auth/login
```

**Request body**

```json
{
  "phone_or_email": "test@gmail.com",
  "password": "j18d1m*01"
}
```

**Successful response**

```json
{
  "status": "success",
  "user": {
    "id": "ad01f75b-041a-4b09-8171-efe09fa4a15c",

    "is_email": true,
```

## 🧠 Frontend Requirements

Please implement:

### ✅ Authentication Logic

* Login form
* Store token securely (HTTP header: `Authorization: Bearer <token>`)
* Logout handling
* Auto-fetch authenticated user (`/auth/me`)

### ✅ Role-Based Access Control

* `superadmin`
* `school_admin`
* `parent`

Each role must see **only its authorized pages and actions**.

### ✅ Protected Routes

* Block unauthenticated access
* Redirect based on role
* Handle expired or invalid tokens gracefully

### ✅ UX & UI

* Institutional, calm, and professional design
* Clear error messages
* Loading states during auth requests
* No fintech-aggressive animations
